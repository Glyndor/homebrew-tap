# The catalogue of mutations: one entry per line, five fields separated by TAB.
#
#   id <TAB> file to mutate <TAB> exact text to replace <TAB> text that replaces it
#        <TAB> tests of tests/ that must fail when the mutation is applied
#
# The text to replace has to appear EXACTLY ONCE in the file: a text that appears nowhere
# changes nothing and proves nothing, and one that appears twice is ambiguous. The runner
# refuses both, so an inert entry cannot sit in this file unnoticed. A text holds no TAB:
# the line carries exactly four, and a fifth would move every field after it.
#
# The tests named by an entry are the ones that must notice when it is applied.
#
# A change that adds a guard adds the entry that breaks it, in the same change,
# naming the suite that notices. tests/mutation/catalog-reaches-every-script.test.sh
# holds the floor of that rule on every pull request: a script under scripts/ that
# no entry mutates fails there, unless its suite is one the runner excludes. It
# cannot count the guards inside a file, so a guard added without its entry to a
# file that already has entries is for the review to catch.
#
# WHAT IS NOT IN THIS FILE
#
# Two suites of tests/ cannot run in the copy the sweep works on, and no entry names
# them. The copy is made with `git archive HEAD`, so it carries no git metadata:
#
#   tests/ci/suites/check-suite-completeness.test.sh
#       It runs the other suites and reads the base commit with `git show HEAD^1:...`.
#       Its verdict lines (the exit status, the count in the sentinel and the sentinel
#       itself) are mutated by entries that name
#       tests/ci/suites/check-suite-completeness-verdict.test.sh, which runs the runner
#       over suites it writes and needs no history.
#   tests/quality/hygiene/check-editorconfig.test.sh
#       It walks the tracked files with `git ls-files`.
#
# Both fail in that copy whatever the mutant is, so a failure there would count as a
# kill that never happened. The runner excludes them by name, on every run, with the
# same reason; the list here and the list in the runner are the same one.
#
# No other suite is excluded: none of them needs the network (the drift watchers
# stub `curl`), and none of them needs a tool this repository does not carry. The
# tools the workflows install for themselves -- `brew`, `scoop`, `reprepro` -- are
# named only inside workflow fixtures, never invoked by a suite.
#
# THE ML-DSA-65 GUARDS ONLY A REAL SIGNATURE REACHES
#
# The pq-* entries below name tests/release/release-signature.test.sh, which
# needs no ML-DSA library. Three guards of the same check are reached only by a
# real ML-DSA-65 signature: the cryptographic verification itself, the walk over
# every configured key, and the refusal of a signature that does not verify.
# tests/release/release-signature/release-signature-mldsa.test.sh kills them, and
# it needs cryptography 50.0.2, which CI installs only in that suite's own job.
# This sweep runs on the runner's python3-cryptography, where that suite fails
# without any mutation, so an entry naming it could not be run here. Each of the
# three was broken by hand and that suite went red for it.
#
# Run: tests/mutation/run-mutations.sh [--list] [<id>]
